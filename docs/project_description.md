## 1. Назначение

`local-llm-runner` — терминальный кодинг-агент, работающий с локальными LLM. Пользователь в терминале ставит задачу на естественном языке, агент читает и изменяет файлы проекта, запускает команды и сообщает результат — так же, как Claude Code, но на модели, запущенной на машине пользователя.

Первый поддерживаемый бэкенд — **LM Studio**: локальный сервер с OpenAI-совместимым API на `http://localhost:1234/v1`.

Ценность для пользователя:

- **Приватность** — код не покидает машину.
- **Работа офлайн и без подписки** — ключ API не нужен.
- **Сравнение моделей** — метрики скорости и расхода токенов после каждой сессии.

## 2. Сценарии использования

| Сценарий | Описание |
|---|---|
| Интерактивная сессия | Пользователь запускает агента в каталоге проекта и ведёт диалог: задаёт вопросы по коду, просит внести изменения. |
| Разовая задача (one-shot) | `--task "..."`: агент выполняет одну задачу и завершается. Подходит для скриптов и сравнения моделей на одинаковой задаче. |
| Выбор модели | Пользователь указывает, какую из моделей LM Studio использовать. |
| Просмотр моделей | Пользователь смотрит, какие модели загружены и доступны. |
| Анализ метрик | После сессии пользователь видит время, число ходов, токены и скорость. |

## 4. Прототип на Bash (эталон поведения)

Прототип лежит в родительском каталоге рабочей копии автора (`../`) и в репозиторий не входит.

| Файл | Что делает |
|---|---|
| `llm-agent.sh` | Запускает [aider](https://aider.chat) против LM Studio. При первом запуске ставит aider в изолированный venv (`~/.local/aidervenv`, через `uv`, Python 3.12). Флаги aider: `--yes-always --no-auto-commits --model openai/<model>`. Эндпоинт — `OPENAI_BASE_URL=http://localhost:1234/v1`, ключ — заглушка. |
| `llm-codex.sh` | Запускает OpenAI Codex CLI (`codex --oss --local-provider lmstudio -m <model>`). При отсутствии ставит через Homebrew. Вне git-репозитория добавляет `--skip-git-repo-check`. One-shot — через `codex exec`. |
| `agent-common.sh` | Общая логика: выбор модели, режим one-shot, запуск агента, сбор и печать метрик. |
| `run-under-pty.py` | Запускает агент в псевдотерминале, чтобы TUI агента работал как обычно, а вывод параллельно сохранялся для подсчёта токенов. Пишет метрики в JSON-файл (`METRICS_FILE`, по умолчанию `/tmp/lm-metrics.json`). |
| `list-models.sh` | Показывает загруженные (`lms ps`) и скачанные (`lms ls`) модели LM Studio. |

Поведение прототипа:

- **Модель:** `--model <name>` > переменная `LOCAL_MODEL` > `ornith-1.5-35b-a3b`.
- **Режимы:** без аргументов — интерактивный; `--task "текст"` — разовая задача с печатью метрик в конце.
- **Метрики:** в one-shot режиме — всегда; в интерактивном — только при `ENABLE_METRICS=1` (через PTY-обёртку).
- **Git:** агент никогда не коммитит — коммитит только пользователь.

Ограничения прототипа, которые устраняет Go-версия:

1. Зависимость от сторонних агентов и рантаймов (Python, `uv`, Homebrew, aider, Codex) и их автоустановка.
2. Токены извлекаются регулярными выражениями из текстового вывода агентов — это хрупко. Codex выводит только общее число токенов, и прототип засчитывает его и в prompt, и в completion, поэтому «Всего токены» для Codex удваивается.
3. Агент работает в каталоге скриптов (`cd "$SCRIPT_DIR"`), а не в каталоге проекта пользователя.
4. `--model` должен идти раньше `--task` (аргументы разбираются двумя последовательными циклами).
5. Нет контроля над инструментами агента и политикой подтверждения действий.

## 5. Функциональные требования

### FR-1. Выбор модели — ✅

Модель определяется по приоритету: флаг `--model` > переменная окружения `LOCAL_MODEL` > значение по умолчанию `ornith-1.5-35b-a3b`. Пустое имя модели (или из одних пробелов) — ошибка использования.

### FR-2. Адрес API — ✅

Адрес OpenAI-совместимого API: флаг `--base-url` > переменная `LOCAL_LLM_BASE_URL` > `http://localhost:1234/v1`. Допускается только абсолютный URL со схемой `http` или `https`, иначе — ошибка использования. Сейчас значение только проверяется: сетевого клиента ещё нет.

### FR-3. Режимы работы — 🟡

- Без `--task` — интерактивный режим (диалог до выхода пользователя).
- `--task "текст"` — one-shot: агент выполняет задачу без вопросов к пользователю и завершается; код выхода 0 при успехе, иначе ≠ 0.
- Флаги указываются в любом порядке.

Сейчас: флаг разбирается и режим определяется, но задача не выполняется.

### FR-4. Версия — ✅

`--version` печатает `local-llm-runner <версия>` в stdout и завершается с кодом 0. Версия берётся из `-ldflags "-X main.version=..."` (`make build` подставляет `git describe`), иначе — из VCS-информации сборки, иначе `dev`.

### FR-5. Справка и ошибки использования — ✅

- `-h`/`--help` печатает описание флагов и переменных окружения в stdout, код выхода 0.
- Неизвестный флаг, лишние позиционные аргументы или невалидное значение — сообщение в stderr и код выхода 2.

### FR-6. Список моделей — ⬜

Аналог `list-models.sh`: показать модели, доступные на сервере LM Studio, с отметкой загруженных. Источник — API сервера (`GET /v1/models`), без вызова CLI `lms`. Форма команды не определена (см. открытые вопросы).

### FR-7. Диалог с моделью — ⬜

Сообщения пользователя отправляются модели вместе с историей диалога; ответ выводится потоково (по мере генерации). Если модель возвращает рассуждения (reasoning), они отображаются отдельно от ответа.

### FR-8. Инструменты агента — ⬜

Модель через tool calling может: читать файлы, искать по файлам, создавать и изменять файлы, выполнять shell-команды. Все файловые операции ограничены рабочей директорией (FR-11), выход за её пределы (включая `..` и симлинки) невозможен.

### FR-9. Подтверждение действий — ⬜

Изменение файлов и выполнение shell-команд в интерактивном режиме требуют подтверждения пользователя. Режим автоподтверждения (аналог `--yes-always` у aider) включается только явным флагом. Политика для one-shot режима — открытый вопрос.

### FR-10. Git только у пользователя — ⬜ (инвариант)

Агент никогда не выполняет `git commit`, `git push` и другие команды, меняющие историю или удалённый репозиторий, если пользователь явно не попросил об этом в текущей сессии. Унаследовано от прототипа (`--no-auto-commits`).

### FR-11. Рабочая директория — ⬜

Рабочая директория агента — каталог, из которого запущена программа (в отличие от прототипа).

### FR-12. Метрики сессии — ⬜

По завершении сессии (в обоих режимах) в stderr печатаются:

| Метрика | Определение |
|---|---|
| Затраты времени | время от начала до конца сессии, секунды |
| Ходов (turns) | число запросов к модели |
| Prompt токены | сумма `usage.prompt_tokens` по всем запросам |
| Completion | сумма `usage.completion_tokens` |
| Всего токены | Prompt + Completion |
| Скорость | Всего токены / Затраты времени, tok/s (как в прототипе) |

Токены берутся только из поля `usage` ответов API, а не из разбора текста. Формат вывода прототипа:

```
──────────────────────────────────────────────────
 Метрики сессии LLM
  Затраты времени : 12.3 с
  Ходов (turns)   : 3
  Prompt токены   : 5120
  Completion      : 870
  Всего токены    : 5990
  Скорость        : 487.0 tok/s (с учётом размышлений/инструментов)
──────────────────────────────────────────────────
```

### FR-13. Прерывание — 🟡

Ctrl+C или SIGTERM отменяют текущий запрос к модели и выполняемую команду, восстанавливают состояние терминала и завершают программу.

Сейчас: корневой контекст отменяется по сигналу, но прерывать пока нечего.

### FR-14. Работа без ключа API — ⬜

Для LM Studio ключ API не требуется и не запрашивается.

## 6. Нефункциональные требования

| ID | Требование |
|---|---|
| NFR-1 | **Локальность.** Программа не обращается к сети, кроме настроенного LLM-эндпоинта. Никакой телеметрии. |
| NFR-2 | **Поставка.** Один бинарный файл без рантайм-зависимостей (Python, Node, `uv`, Homebrew не нужны). |
| NFR-3 | **Платформы.** macOS arm64 — основная; Linux — желательно; Windows — не целевая. |
| NFR-4 | **Безопасность.** Агент не читает и не пишет файлы вне рабочей директории; команды выполняются только по правилам FR-9. |
| NFR-5 | **Отзывчивость.** Токены ответа отображаются сразу по мере поступления; интерфейс не блокируется во время генерации. |
| NFR-6 | **Качество.** `make check` зелёный; unit-тесты работают без сети и LM Studio. |

## 8. Вне рамок (пока)

- Облачные провайдеры (OpenAI, Anthropic) и другие локальные серверы (Ollama, llama.cpp). Архитектура это не должна исключать: протокол OpenAI-совместимый.
- Загрузка и скачивание моделей — это делается в LM Studio.
- GUI и плагины для IDE.
- Автоматические git-коммиты.

## 9. Открытые вопросы

1. Короткое имя команды: `local-llm-runner` длинное для ежедневного использования.
2. Терминальный интерфейс: построчный режим на стандартной библиотеке или TUI-библиотека (например, Bubble Tea).
3. Форма команды списка моделей (FR-6): флаг `--list-models` или подкоманда `models`.
4. Политика подтверждений в one-shot режиме (FR-9): запрещать изменения, требовать флаг автоподтверждения или разрешать всё.
5. Определение скорости (FR-12): в прототипе tok/s = все токены / общее время, что смешивает обработку промпта и генерацию. Добавить ли скорость генерации (completion / время генерации)?
6. Файл конфигурации (например, `~/.config/local-llm-runner/config.toml`).
7. Сохранение и возобновление сессий.
8. Чтение агентом инструкций проекта (`AGENTS.md`) в духе Claude Code.
