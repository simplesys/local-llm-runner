## 1. Назначение

`locallm` — терминальный кодинг-агент для локальных LLM. Пользователь ставит задачу на естественном языке, агент читает и изменяет файлы проекта, запускает команды и сообщает результат — как Claude Code или Codex CLI, но на модели, запущенной на машине пользователя.

Первый поддерживаемый бэкенд — **LM Studio**: локальный сервер с OpenAI-совместимым API на `http://localhost:1234/v1`.

Два равноправных режима работы:

1. **интерактивный** — диалог в терминале;
2. **вызов извне** — другим инструментом или моделью. Типовой сценарий: планирование облачной моделью → реализация локальной моделью → результат обратно облачной модели на ревью.

Ценность для пользователя:

- **Приватность** — код не покидает машину.
- **Работа офлайн и без подписки** — ключ API не нужен.
- **Измеримость** — метрики каждой сессии сохраняются файлом, прогоны разных моделей сравнимы.
- **Контролируемость** — потолки расходов, песочница, подтверждение действий, ограниченная область правок.

## 2. Сценарии использования

| Сценарий | Описание |
|---|---|
| Интерактивная сессия | Пользователь запускает агента в каталоге проекта и ведёт диалог: спрашивает по коду, просит внести изменения. |
| Разовая задача (one-shot) | `--task "..."`: агент выполняет одну задачу и завершается. Подходит для скриптов и сравнения моделей на одинаковой задаче. |
| Выбор и переключение модели | Без явного указания сессия работает с уже загруженной моделью. Пользователь называет модель флагом или командой `/model` — тогда предыдущая модель полностью выгружается. |
| Просмотр моделей | `--list-models`: какие модели есть, какие загружены, какие умеют вызывать инструменты. |
| Анализ и сравнение метрик | После каждой сессии — метрики в stderr и файл на сессию в каталоге метрик. |

## 3. Текущее состояние

| Компонент | Состояние |
|---|---|
| Go-приложение | Работает end-to-end: выбор и переключение модели, потоковый диалог, инструменты (файлы, поиск, shell), песочница, подтверждения, метрики, история сессий, построчный интерфейс с командами. |
| Терминальный интерфейс | Построчный (stdin/stdout). Полноэкранный интерфейс со статусной строкой и пикерами — запланирован. |
| Bash-прототип | Работает (см. раздел 4), но больше не является ориентиром развития: Go-версия покрывает его функциональность без Python, `uv`, Homebrew, aider и Codex CLI. |

Статусы требований: ✅ реализовано и покрыто тестами · 🟡 частично · ⬜ не реализовано.

## 4. Прототип на Bash (историческая справка)

Прототип лежит в родительском каталоге рабочей копии автора (`../`) и в репозиторий не входит. Он оборачивал сторонних агентов aider и Codex CLI через Python, `uv` и Homebrew, брал токены регулярными выражениями из текстового вывода и работал в каталоге скриптов, а не проекта. Go-версия убрала эти ограничения: рантаймов нет, токены берутся из поля `usage` ответов API, рабочая директория — каталог запуска.

Формат печати метрик унаследован от прототипа намеренно, чтобы старые и новые замеры оставались сравнимыми (FR-12).

## 5. Функциональные требования

### FR-1. Выбор модели — ✅

Модель определяется по приоритету: флаг `--model` > переменная `LOCAL_MODEL` > файл настроек. Если модель не названа ни одним из них, сессия работает с моделью, которая уже загружена на сервере: берётся первая загруженная модель с возможностью `tool_use`, незагруженная модель автоматически не выбирается никогда. Модель, не заявившая `tool_use`, выбирается с предупреждением. Если модель не названа и ни одна модель с `tool_use` не загружена: в неинтерактивном режиме — ошибка с подсказкой загрузить модель в LM Studio или передать `--model`; в интерактивном режиме сессия начинается без модели, любой ввод отклоняется предупреждением, пока пользователь не выберет модель командой `/model <id>`.

### FR-2. Адрес API — ✅

Адрес OpenAI-совместимого API: флаг `--base-url` > переменная `LOCAL_LLM_BASE_URL` > `http://localhost:1234/v1`. Допускается только абсолютный URL со схемой `http` или `https`.

### FR-3. Режимы работы — ✅

- Без `--task` — интерактивный режим (диалог до выхода пользователя).
- `--task "текст"` — one-shot: одна задача и выход; код выхода отражает результат (раздел 7).
- Флаги указываются в любом порядке.

### FR-4. Версия — ✅

`--version` печатает `locallm <версия>` в stdout и завершается с кодом 0. Версия берётся из `-ldflags "-X main.version=..."`, иначе из VCS-информации сборки, иначе `dev`.

### FR-5. Справка и ошибки использования — ✅

- `-h`/`--help` печатает флаги, переменные окружения, путь к файлу настроек и коды выхода в stdout, код выхода 0.
- Неизвестный флаг, лишние позиционные аргументы или невалидное значение — сообщение в stderr и код выхода 2.

### FR-6. Список моделей — ✅

`--list-models` печатает таблицу: идентификатор, состояние (`loaded`/`not-loaded`), поддержка инструментов, размер контекста, квантизация. Источник — нативный API LM Studio `GET /api/v0/models`; CLI `lms` для этого не нужен. В интерактивном режиме то же делают команды `/models` и `/model` без аргумента.

### FR-7. Диалог с моделью — ✅

Сообщения пользователя отправляются модели вместе с историей диалога; ответ выводится потоково по мере генерации. Рассуждения модели (`reasoning_content`) выводятся отдельно от ответа: ответ — в stdout, рассуждения — в stderr.

### FR-8. Инструменты агента — ✅

Через tool calling модель может:

| Инструмент | Назначение |
|---|---|
| `read_file` | чтение файла с номерами строк, с параметрами `offset` и `limit` |
| `list_dir` | список каталога; служебные каталоги (`.git`, `node_modules`, `vendor`, `dist`, `bin`, `target`, `build`, `.venv`, каталоги IDE) пропускаются |
| `write_file` | создание или полная перезапись файла, с созданием промежуточных каталогов |
| `edit_file` | замена точного фрагмента; без `replace_all` вхождение должно быть единственным |
| `glob` | поиск файлов по шаблону имени, новые первыми |
| `grep` | поиск по содержимому регулярным выражением, с контекстными строками |
| `shell` | выполнение команды в рабочей директории с таймаутом и ограничением вывода |

Ограничения: файл больше 256 КБ не читается целиком, вывод инструмента обрезается до 32 КБ с явной пометкой, список каталога обрывается после 500 записей, поиск останавливается после 200 совпадений, бинарные файлы пропускаются. Shell-команда убивается через две минуты; модель может параметром `timeout_seconds` запросить только меньший срок, больший не действует. Все файловые операции ограничены рабочей директорией; выход за её пределы через `..`, абсолютный путь или симлинк невозможен.

### FR-9. Подтверждение действий — ✅

Изменяющие действия (`write_file`, `edit_file`, `shell`) требуют подтверждения пользователя. Ответ `y` или `yes` разрешает действие, любой другой ответ и конец ввода — запрещают; при отказе сессия завершает текущую задачу. Флаг `--yes` включает автоподтверждение (обязателен для неинтерактивных прогонов без пользователя).

### FR-10. Git только у пользователя — ✅ (инвариант)

Агент не выполняет команды, меняющие историю или удалённый репозиторий. Инструмент `shell` отклоняет команды, начинающиеся с `git commit`, `git push`, `git reset --hard`, `git rebase`, `git checkout -b`, `git branch`, `git tag`, `git remote` (регистр и лишние пробелы не помогают их обойти). Команды чтения (`git status`, `git diff`) разрешены.

### FR-11. Рабочая директория — ✅

Рабочая директория агента — каталог запуска; флаг `--workspace` позволяет указать другой. Каталог должен существовать.

### FR-12. Метрики сессии — ✅

По завершении сессии метрики печатаются в stderr в формате прототипа:

```
──────────────────────────────────────────────────
 Метрики сессии LLM
  Затраты времени : 12.3 с
  Ходов (turns)   : 3
  Prompt токены   : 5120
  Completion      : 870
  Всего токены    : 5990
  Скорость        : 487.0 tok/s (с учётом размышлений/инструментов)
──────────────────────────────────────────────────
```

Токены берутся только из поля `usage` ответов API. Дополнительно пишется файл на сессию в каталог метрик (`--metrics-dir`, по умолчанию каталог настроек): идентификатор и проект сессии, модель, адрес API, уровень песочницы, режим, статус (`ok`, `error`, `limit`, `canceled`), причина остановки последней задачи (`done`, `max_turns`, `max_tokens`, `max_tools`, `deadline`, `denied`, `canceled`; у сорвавшегося запроса причины нет), время начала и конца, метрики. Именно этот файл делает прогоны разных моделей сравнимыми.

### FR-13. Прерывание — ✅

Ctrl+C в интерактивном режиме прерывает текущую задачу; второе нажатие в течение двух секунд завершает программу. Ctrl+D и `/exit` завершают сессию. SIGTERM отменяет всё дерево операций. В любом случае метрики печатаются, а сессия закрывается корректно.

### FR-14. Работа без ключа API — ✅

Для LM Studio ключ API не требуется и не передаётся.

### FR-15. Переключение модели по явному указанию — ✅

Программа загружает и выгружает модели только тогда, когда модель названа явно — флагом `--model`, переменной `LOCAL_MODEL`, файлом настроек или командой `/model <id>`. Если названная модель уже загружена и других разговорных моделей в памяти нет, ничего не происходит. В остальных случаях все загруженные модели выгружаются и загружается названная: одновременно в памяти держится одна модель. Когда модель не названа, сессия работает с тем, что уже в памяти, и `lms` не вызывается вовсе. Переключение выполняется через CLI `lms` из состава LM Studio (`lms unload -a`, затем `lms load <id> -y [--context-length N]`), готовность подтверждается по API. Прогресс виден пользователю. Файловый лок в каталоге настроек не даёт двум экземплярам программы переключать модель одновременно. Флаг `--no-switch` отключает управление моделями; `--context-length` задаёт размер контекста при загрузке. Если `lms` не найден, а нужная модель уже загружена — работа продолжается с предупреждением.

### FR-16. Песочница — ✅

Shell-команды выполняются под изоляцией. Уровни: `seatbelt` (macOS), `none` (остальные платформы; Linux — запланирован уровень `landlock`). Политика: `required` (без песочницы команды не выполняются), `best-effort` (по умолчанию: работаем на доступном уровне, ограничение выводится предупреждением), `off`. Уровень отображается в результате инструмента и попадает в файл метрик. В песочнице разрешена запись только в рабочую директорию, каталоги кэшей сборки и временный каталог; сеть запрещена.

### FR-17. Потолки расходов — ✅

`--max-turns`, `--max-tokens` и `--timeout` ограничивают одну задачу. При упоре в потолок работа прекращается штатно: печатается причина, метрики получают статус `limit`, в one-shot режиме код выхода — 3. Четвёртый потолок — число вызовов инструментов за задачу (`max_tools`) — реализован в агенте, но флага и настройки у него нет: снаружи он не задаётся и по умолчанию не ограничивает ничего.

### FR-18. Настройки между сессиями — 🟡

Настройки хранятся файлом `settings.json` в каталоге настроек (`os.UserConfigDir()/locallm`, переопределяется переменной `LOCAL_LLM_CONFIG_DIR`): модель, адрес API, каталог метрик, политика песочницы, размер контекста, автоподтверждение, ретенция истории. Приоритет: флаги > переменные окружения > файл > значения по умолчанию. Повреждённый файл не мешает работе: печатается предупреждение, применяются значения по умолчанию.

Сейчас: файл читается и применяется. Команда `/settings` для правки из интерфейса — запланирована.

### FR-19. История сессий — 🟡

Каждая сессия пишется в файл JSONL в каталоге сессий вместе с индексом: сообщения, вызовы инструментов, результаты, метрики. Записи появляются в файле по ходу задачи — сразу после каждого хода модели и каждого результата инструмента, а не по её завершении: за работой агента можно следить в реальном времени (`tail -f`), а прерванная, зациклившаяся или упавшая сессия сохраняет всё, что успело произойти. Ретенция — три одновременных ограничения, срабатывает то, которое достигнуто раньше: 50 сессий, 500 МБ суммарно, 90 дней. Любое ограничение можно обнулить по отдельности, все три сразу — нельзя; историю можно отключить целиком (`--no-session` или настройка). Самая свежая сессия не удаляется никогда.

Сейчас: запись, индекс, ретенция и восстановление индекса сканом работают. Возврат к прошлым сессиям (`/sessions`, `/resume`, `--session`) — запланирован.

### FR-20. Очистка контекста — 🟡

`/clear` забывает диалог и начинает новую сессию (новый файл истории). Сжатие истории `/compact` — запланировано.

### FR-21. Область правок — 🟡

Замысел: изменения выполняются только внутри заданного списка путей рабочей директории, чтение при этом не ограничивается.

Сейчас: проверка реализована в файловых инструментах поверх `os.Root`, но сессия её не включает — список путей пуст, поэтому правки ограничены только рабочей директорией (FR-8). Флаг и настройка, которыми список задаётся, — запланированы.

### FR-22. Инструкции проекта — ✅

Агент читает `AGENTS.md` (или `CLAUDE.md`, если первого нет) из рабочей директории и передаёт его содержимое модели в системном промпте целиком. Ограничения на размер файла нет: правила проекта не обрезаются, иначе агент работал бы по половине инструкции, а разработчику пришлось бы следить за размером файла.

## 6. Нефункциональные требования

| ID | Требование |
|---|---|
| NFR-1 | **Локальность.** Программа не обращается к сети, кроме настроенного LLM-эндпоинта. Никакой телеметрии. |
| NFR-2 | **Поставка.** Один бинарный файл без рантайм-зависимостей (Python, Node, `uv`, Homebrew не нужны). Для переключения моделей нужен `lms` из состава LM Studio. |
| NFR-3 | **Платформы.** macOS, Linux и Windows поддерживаются наравне по функциональности; различается только уровень песочницы. Windows на реальной машине пока не проверен. |
| NFR-4 | **Безопасность.** Агент не читает и не пишет файлы вне рабочей директории; команды выполняются под песочницей и только по правилам FR-9 и FR-10. Вывод модели считается недоверенным вводом. |
| NFR-5 | **Отзывчивость.** Токены ответа отображаются сразу по мере поступления. |
| NFR-6 | **Качество.** `make check` зелёный; unit-тесты работают без сети и LM Studio. |

## 8. Запланировано

Полноэкранный интерфейс (Bubble Tea в inline-режиме) со статусной строкой (`/statusline`), пикером модели, `/settings`, `/sessions`, `/resume`, `/compact` и рендерингом markdown; карта проекта как первый слой навигации; контракт вызова извне (файл задачи → файл результата и патч, `--report md`, продолжение по `--session`); MCP-клиент и MCP-серверный режим; скиллы (`.agents/skills/`); движок workflow (фазы, шаги, роли как наборы параметров); `--replay` для сравнения моделей; песочница Linux на Landlock; проверка на Windows.

## 9. Вне рамок

- Облачные провайдеры (OpenAI, Anthropic) и другие локальные серверы (Ollama, llama.cpp). Архитектура это не исключает: протокол OpenAI-совместимый.
- Загрузка и скачивание моделей из сети — это делается в LM Studio.
- GUI и плагины для IDE.
- Автоматические git-коммиты.
- **Subagents.** На одной локальной модели параллелизм фиктивен: модель в памяти одна, переключение контекстов срывает prompt-кэш, а цепочки вызовов без присмотра множат ошибки tool calling.
- **Собственная карта символов кода** (regex-сигнатуры, парсеры, tree-sitter). Замеры показали, что она не влезает в контекст без ранжирования; навигация строится на дереве файлов, инструментах поиска и опциональном внешнем индексаторе через MCP.
- **Семантический поиск на эмбеддингах** и **LSP-клиент**: несопоставимая сложность при неочевидной пользе для локальных моделей.
- Методология разработки: как писать планы, как разбивать задачи, какие бывают роли. Проект даёт механизм, а не методику.
